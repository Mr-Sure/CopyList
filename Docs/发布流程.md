# CopyList 发布流程

> 面向维护者与 AI 的标准化发布手册。约定「谁负责什么」：**人/AI 只负责写 CHANGELOG 条目，其余全部由 `Scripts/build.sh` 自动完成**。

---

## 一、一句话流程

```bash
# 1) 在 CHANGELOG.md 顶部写好本次版本条目（分类 + 用户可感知的描述）
# 2) 预演，检查将要生成的 commit 与 Release 文案
DRY_RUN=1 bash Scripts/build.sh
# 3) 正式发布（递增版本 → 编译 → 签名 → 打包 → 提交 → 打 tag → 推送 → 创建 Release）
bash Scripts/build.sh
```

---

## 二、版本号规则

- 采用**语义化版本** `MAJOR.MINOR.PATCH`，日常发布只递增 `PATCH`。
- `CFBundleVersion`（构建号）每次发布 +1，与版本号一一对应，用于区分同版本的多次构建。
- 版本号由脚本自动递增，**不要手工改 `Info.plist`**（改了会被脚本覆盖，且容易与 tag 冲突）。

---

## 三、CHANGELOG.md 规范（发布文案的唯一数据源）

`CHANGELOG.md` 是**唯一**需要人工/AI 维护的发布文案，脚本会把它同时用作：

- **commit message 正文**
- **GitHub Release notes**

格式要求（脚本按此正则解析：`^## \[x.y.z\]`）：

```markdown
## [1.3.25] - 2026-09-14

### 修复

- **全屏下状态栏图标偶发不显示**：一句话说明现象与修复后的行为

### 新增

- ...

### 优化

- ...
```

写作要求：

| 要求 | 说明 |
|------|------|
| 写「用户可感知的变化」 | 「修复全屏下图标不显示」✅ ；「重构 `applyStatusItemIcon`」❌ |
| 分类固定 | `新增` / `修复` / `优化` / `变更` / `文档`，无内容的分类直接省略 |
| 标题格式严格 | `## [x.y.z] - YYYY-MM-DD`，三级标题 `###` |
| 新条目放最上方 | 紧随 `## [未发布]` 之后 |
| 缺失也不阻塞 | 若忘记写，脚本会自动插入一条草稿（列出改动文件与提交），并提示补充 |

版本标题行之后、下一个 `## [` 之前的内容，被称为**版本条目正文**。

---

## 四、Commit 规范

脚本自动生成的 commit 形如：

```
release(v1.3.25): 修复全屏下状态栏图标偶发不显示

## [1.3.25] - 2026-09-14

### 修复

- **全屏下状态栏图标偶发不显示**：...

---
构建号: 26 | 构建时间: 2026-09-14 11:20 | 产物: CopyList.dmg
```

- 标题：`release(vX.Y.Z): <版本条目首条摘要>`
- 正文：版本条目正文（与 Release notes 同源，保证「提交记录 = 发布说明」）
- **不要手工 `git commit` 版本文件**，否则会造成版本号与 tag 不一致。

其它非发布类改动（文档、脚本、CI）使用常规类型即可：`docs:`、`fix:`、`feat:`、`chore:`、`refactor:`，中文描述。

## 五、脚本自动完成的事（`Scripts/build.sh`）

| # | 步骤 | 说明 |
|---|------|------|
| 1 | 读取当前版本 | 来自 `Resources/Info.plist` |
| 2 | 变更检测 | 未提交改动 / 暂存改动 / 未跟踪文件 / **自上次发布（`version.json` 变更）以来的新提交** |
| 3 | 递增版本 | `PATCH + 1`、构建号 `+ 1`，写回 `Info.plist`（含 `CLBuildTime`） |
| 4 | 取发布文案 | 从 `CHANGELOG.md` 抽取本版本条目；缺失则自动插入草稿 |
| 5 | 编译 | `swiftc` 全量源码 |
| 6 | 拷贝资源 | `statusbar_icon.png`；缺 `AppIcon.icns` 时由 `AppIcon.iconset` 用 `iconutil` 生成 |
| 7 | 签名 | 优先固定证书 `CopyListDev`，缺失回退 ad-hoc 并提示；随后 `codesign -vvv` 校验 |
| 8 | 安装 | 替换 `/Applications/CopyList.app` 并启动（无权限时跳过，不中断） |
| 9 | `version.json` | 供应用内「检查更新」读取 |
| 10 | DMG | 打包 `CopyList.dmg`（旧包备份为 `.dmg.bak`） |
| 11 | Git | `git add -A` + 规范化 commit + 打 tag `vX.Y.Z` |
| 12 | 推送 | `master` 与 tag |
| 13 | Release | `gh release create`，notes 使用版本条目正文 + 构建信息表格 |
| 14 | 收尾 | 打印版本、DMG、tag、Release 链接 |

## 六、环境变量开关

| 变量 | 作用 | 典型场景 |
|------|------|----------|
| `DRY_RUN=1` | 空跑：不写文件、不编译、不安装、不提交、不推送，仅打印将要产生的版本号、commit message 与 Release notes | AI 预演、文案自查 |
| `FORCE_BUMP=1` | 即使没有检测到变更也递增版本 | 重新发布、修文案后重发 |
| `SKIP_INSTALL=1` | 跳过安装到 `/Applications` 与启动应用 | CI / 无图形界面的环境 |
| `SKIP_PUSH=1` | 跳过 `git push` 与 Release 创建（仍会本地提交与打 tag） | 先本地验证产物 |

组合示例：

```bash
DRY_RUN=1 bash Scripts/build.sh          # 只演算，不改任何东西
SKIP_INSTALL=1 bash Scripts/build.sh     # 构建 + 发布，但不动本机安装
FORCE_BUMP=1 bash Scripts/build.sh       # 强制递增版本并发布
```

## 七、AI 自动化契约

AI 执行发布时，必须按以下顺序动作，不做额外发挥：

1. **改代码**：完成需求并保证 `swiftc` 通过（`-typecheck` 即可快速验证）。
2. **写 CHANGELOG**：在 `CHANGELOG.md` 顶部插入 `## [<当前 PATCH+1>] - <今天日期>`，按分类写「用户可感知的变化」。
3. **预演**：运行 `DRY_RUN=1 bash Scripts/build.sh`，检查输出的 commit message 与 Release notes 是否符合预期（文案错了退回第 2 步）。
4. **发布**：运行 `bash Scripts/build.sh`。
5. **校验**：执行下节第 1~3 条命令确认落地。
6. **汇报**：给出「版本号、构建号、commit、tag、Release 链接、本地安装状态」六项。

**禁止事项**

- ❌ 改写已推送的提交历史（`--amend`、`rebase` 后又 force push）
- ❌ 对 `master` 执行 `push --force`
- ❌ 手工移动/删除已发布的 tag（必要时先删 Release 再删 tag，见第九节）
- ❌ 删除 `CHANGELOG.md` 中的历史条目（它同时是归档）
- ❌ 手工编辑 `Info.plist` 的版本字段或 `version.json`

## 八、发布后校验

```bash
# 1) 本机安装是否为最新
/usr/libexec/PlistBuddy -c "Print :CFBundleShortVersionString" /Applications/CopyList.app/Contents/Info.plist
ls -l /Applications/CopyList.app/Contents/Resources/     # 确认 statusbar_icon.png 存在
pgrep -lf "/Applications/CopyList.app"                   # 确认新进程已启动

# 2) 远程 Release 与资产
gh release view vX.Y.Z --repo Mr-Sure/CopyList --json tagName,name,assets \
  --jq '{tag:.tagName,name:.name,assets:[.assets[]|{name:.size}]}'

# 3) 本地产物
ls -lh CopyList.dmg && git --no-pager log --oneline -1 && git --no-pager status --short
```

常见现象说明：

- **替换包后"无感"**：CopyList 是 `LSUIElement` 常驻应用，重启只表现为状态栏图标闪一下，不会弹窗。
  想确认版本：状态栏图标 → 齿轮 → 关于，查看「版本」与「构建时间」。
- **菜单栏图标未见**：先确认没有被 macOS 因菜单栏空间不足而隐藏（第三方状态项过多时会被挤掉），
  再看应用日志是否输出「未找到 statusbar_icon.png」。

---

## 九、回滚

```bash
# 1) 删除远程 Release（保留 tag）
gh release delete vX.Y.Z --repo Mr-Sure/CopyList --yes

# 2) 若需重新发布同一版本号：删远程 tag 后再删本地 tag，然后重新运行 build.sh
git push origin :refs/tags/vX.Y.Z
git tag -d vX.Y.Z
```

版本号回退：直接改 `Resources/Info.plist` 的 `CFBundleShortVersionString` / `CFBundleVersion` 后重新构建（仅限尚未发布到远程的情况）。
